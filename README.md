# Solartek SMS Auth

Самостоятельный плагин входа по SMS для WordPress и WooCommerce. Мастер задаёт адрес совместимого SMS-сервиса, путь API, ключ, лимиты, формы и источник обновлений. По умолчанию используется `https://sms.solartek.ru`, но адрес можно изменить в интерфейсе.

Поддерживаются мобильные номера России (+7 9…). Для другого SMS-провайдера нужен совместимый API challenges; простой замены адреса недостаточно для сервиса с другим протоколом.

## Установка

1. Скачайте **solartek-sms-auth.zip** из [последнего релиза](https://github.com/yavasilek/solartek-sms-auth/releases/latest). Автоматический архив исходников GitHub для установки не используется.
2. В WordPress откройте «Плагины → Добавить плагин → Загрузить», установите ZIP и включите плагин.
3. Пройдите мастер «Настройки → SMS-вход»: сервис и ключ → формы и лимиты → обновления → включение входа.
4. У каждого сайта свои ключ, политика и лимиты. Они хранятся в базе сайта и сохраняются при обновлении. Править `wp-config.php` не нужно.

Требования: WordPress 6.5+, WooCommerce, PHP 8.1+, OpenSSL, GD с FreeType. Для проверки обновлений нужен PHP ZIP. Ключ API хранится отдельно от остальных настроек, с шифрованием AES-256-GCM и ключом из солей данного WordPress. После смены солей ключ API нужно ввести заново.

Первое действие называется «Пройти проверку». SMS отправляется после CAPTCHA и нажатия «Получить SMS». Согласие обязательно. Встроены лимиты по номеру, IP, браузеру и сайту. По умолчанию SMS-вход доступен только покупателям и подписчикам без привилегированных прав. На шаге «Формы и ограничения» администратор может разрешить вход всем ролям, включая администраторов, менеджеров и пользовательские группы. Это отдельная настройка каждого сайта; обновление само её не включает. Проверка доступности в мастере не отправляет SMS и не подтверждает действительность ключа.

При разрешении всех ролей правильный SMS-код авторизует существующего владельца номера с его текущими правами. Новый аккаунт по-прежнему создаётся только с ролью покупателя. Заблокированные и объединённые аккаунты не допускаются, конфликт нескольких владельцев номера требует обычного входа по паролю. Объединение аккаунтов сотрудников остаётся недоступным независимо от настройки входа.

## Поиск пользователей по телефону

В разделе WordPress «Пользователи» штатная строка поиска также ищет по подтверждённому SMS-номеру, телефону покупателя (`billing_phone`) и телефону доставки (`shipping_phone`). Можно ввести полный российский номер с `+7`, `8` или без кода страны, с пробелами, скобками и дефисами, либо часть номера от 4 цифр. Поиск по логину, имени и email, фильтры ролей и пагинация сохраняются. Расширение работает только в этом разделе для сотрудников с правом просмотра пользователей, в том числе до включения SMS-входа; открытые API и поиск пользователей в других частях сайта не меняются. Новые настройки и перенос данных не нужны.

Рядом с email в таблице расположен столбец «Телефон». Он показывает номера с пометками «SMS подтвержден», «Покупатель» и «Доставка». Одинаковый номер из нескольких полей выводится один раз с перечислением источников; разные номера видны отдельно. Столбец можно скрыть через штатные «Настройки экрана». На телефоне он доступен при раскрытии подробностей строки, как остальные дополнительные столбцы WordPress.

## Один модуль для нескольких проектов

Канонический код находится в этом репозитории. Любой проект, которому нужна правка SMS-модуля, использует этот checkout или свою ветку/копию этого же репозитория:

```powershell
git clone https://github.com/yavasilek/solartek-sms-auth.git
cd solartek-sms-auth
git switch -c codex/my-change
# внести изменения
python scripts/test.py
python scripts/build.py
# commit, push и merge в main
```

После push с изменениями кода в `main` GitHub Actions выполняет проверки на PHP 8.1 и 8.4, увеличивает patch-версию (или принимает вручную повышенную версию), создаёт тег и публикует установочный ZIP, контрольную сумму и `release.json`. Настройки и ключи сайтов в Git не попадают.

Все сайты с тем же источником `yavasilek/solartek-sms-auth` получают один стабильный релиз штатным механизмом обновлений WordPress. Автоустановка включается в мастере. Собственная задача `ssa_check_updates` проверяет релизы дважды в сутки и обновляет только этот модуль, даже если стандартная проверка WordPress не запланирована. Нужны WP-Cron/системный cron, разрешения файлов и разрешённые хостингом обновления. Это периодический процесс, а не мгновенная синхронизация файлов. Можно запустить проверку из мастера и обновить вручную в списке плагинов.

Включённое автообновление разрешает замену установленного кода этого модуля релизом даже на сайте внутри Git checkout. Эта настройка не меняет VCS-политику для других плагинов. Разработку ведите в общем репозитории: правки в установленном модуле будут заменены следующим релизом.

Изменения файлов непосредственно на сервере **не отправляются в Git автоматически**. Их нужно внести в общий репозиторий, проверить и объединить в `main`. Сайты не получают Git-токены и не могут публиковать код друг другу.

## Обновления и сохранность данных

Плагин использует свой `Update URI`, проверяет стабильный релиз, источник архива, размер, SHA-256 и структуру ZIP до установки. Конфигурация не входит в архив, поэтому обновление с другого проекта не заменяет адрес, ключ или лимиты сайта. При недоступности GitHub вход продолжает работать; откладывается проверка обновления.

При переносе существующей интеграции сохраняются функции совместимости `moto_*` и метаданные телефонов, пользователей и объединений. Старые MU-модули должны быть заменены совместимыми загрузчиками, чтобы две реализации не запускались одновременно. Делайте такую миграцию с проверкой исходных хешей и rollback, а не простым копированием ZIP поверх MU-файлов.

## Разработка и проверки

`python scripts/test.py` проверяет PHP/JS, ядро авторизации, CAPTCHA, существующие аккаунты/склейку, профиль, настройки и updater. Провайдер в тестах изолирован; реальных SMS и заказов нет. `python scripts/build.py` собирает воспроизводимый ZIP только из `plugin/solartek-sms-auth`.

API создания challenge: `POST {service_url}{api_path}` с Bearer-ключом и Idempotency-Key. Подтверждение: `POST {service_url}{api_path}{challenge_id}/verify/`. HTTPS обязателен; редиректы с ключом отключены. CAPTCHA создаётся самим WordPress.
